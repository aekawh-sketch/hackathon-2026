# Контекст для агента

Прочитай этот файл целиком перед работой. Источник правды по продукту — [`space-map/TZ.md`](space-map/TZ.md), по текущему состоянию — [`space-map/docs/STATUS.md`](space-map/docs/STATUS.md).

## Что за проект

Хакатон, кейс ТТК «Карта пространства» (PDF — `space-map/presentation/`). Срок — **48 часов, ≈ до 25.10.2026**.

Веб-сервис (PWA):
- **кабинет организатора** — рисует или загружает 2D-план, ставит места, снимает телефоном полную фотосферу 360° × 180°, публикует карту по постоянной ссылке или `<iframe>`;
- **карта посетителя** — открывается с телефона без входа: план, поиск, карточки мест, маршрут, панорамы, прогулка по маршруту в панорамах, 3D-вид.

Жюри смотрит на: удобство с телефона, стабильность, скорость загрузки карт и панорам, защиту доступа (ТЗ, раздел 1).

## Главное правило приоритета

Сначала всё с этапом **К1** и чек-лист приёмки (ТЗ 11.2). **К2 и К3 не начинать, пока чек-лист К1 не пройден.** Один этаж в первой версии.

## Стек (решения владельца — не менять без него)

| Часть | Технология |
|---|---|
| Фронт | React 19 + TypeScript + Vite 8, React Router 8 |
| 2D-план (редактор и посетитель) | Konva.js / react-konva — один код отрисовки |
| Панорамы | Photo Sphere Viewer 5 + markers-plugin |
| 3D-вид | three.js, модель строится из плана (`buildModel3D`), выгрузка `.glb` |
| Бэкенд | **Node.js**: Fastify + TypeScript, TypeBox → OpenAPI, Drizzle ORM |
| БД | PostgreSQL; очередь задач — таблица `jobs` со `SKIP LOCKED`, без Redis |
| Файлы | S3-совместимое (MinIO в docker-compose), через абстракцию хранилища |
| Склейка | Python-воркер, CLI-конвейер **Hugin** (не OpenCV Stitcher — он не даёт полную сферу) |
| Маршруты | A* и Дейкстра по явному графу |
| Android | позже: Capacitor + Kotlin (ТЗ 17) |

Не используем: Wi-Fi и BLE для позиционирования, Kubernetes, GraphQL, Redis/Celery.

## Запуск и проверки

```bash
cd space-map
npm install
npm test            # map-core (22 теста) + web (4 теста)
npm run typecheck
npm run dev:web     # http://localhost:5173/m/demo ; QR-якорь: /m/demo?a=ENTRANCE ; кабинет — /app
npx -w apps/web vite build

# бэкенд (базы spacemap и spacemap_test, services/api/.env по образцу .env.example)
npm run seed -w services/api   # миграции + демо-организатор + опубликованная площадка demo
npm run dev:api                # :8080, OpenAPI — /api/docs; Vite проксирует /api, /p, /files
npm test -w services/api       # 12 тестов на базе spacemap_test
```

Локально: Node 22, Python 3.13, PostgreSQL 16 (Homebrew, запущен), Docker Desktop. Hugin на Mac не установлен — только в контейнере воркера.

## Что готово

См. `space-map/docs/STATUS.md`. Коротко: ядро `map-core` с тестами; демо-площадка (`demoVenue()`: 6 помещений, 9 мест, 3 связанные панорамы, QR-якорь); карта посетителя (план, поиск, маршрут, панорамы, прогулка, 3D + `.glb`); демо-панорамы Poly Haven (CC0, `apps/web/public/demo/panoramas/CREDITS.md`).

**В браузере и на телефоне ещё не проверено:** панорамы, 3D, жесты на плане.

## Следующие шаги (по ТЗ 12.4)

1. **Бэкенд `services/api`**: вход (argon2id, cookie `httpOnly` + CSRF), площадки с одним владельцем, документ карты с `revision` (409 при конфликте, 422 при битых ссылках — `validateReferences`), публикация снимком в хранилище, `GET /p/{slug}/latest.json`, загрузки частями. Контракт — ТЗ 9 и 10. Фронт уже ждёт `/p/{slug}/latest.json` (`apps/web/src/api.ts`), dev-прокси на `:8080`.
2. **Воркер склейки** `services/worker` + Docker с Hugin: конвейер из ТЗ 5.5 (`pto_gen` → `cpfind --multirow` → `cpclean` → `autooptimiser -a -m -l -s` → `pano_modify --fov=360x180 --canvas=4096x2048` **без `--crop=AUTO`** → `nona` + `enblend`), проверка покрытия ≥ 99 %, понятные ошибки с номерами кадров. Прогнать на реальном многорядном наборе как можно раньше — главный риск проекта.
3. **Кабинет организатора**: вход, площадки, редактор плана (подложка + калибровка, помещения, проходы, граф, места), панорамы (привязка, ориентация по одной двери `headingFromCorrespondence`, «Принять все» — `acceptSuggestions`), публикация, `<iframe>`.
4. **Экран съёмки** в браузере (ТЗ 5.4).
5. **Деплой** по HTTPS (без HTTPS не работают камера и датчики).

## Правила для агента

- **Не трогать `planCaptureTargets`** в `space-map/packages/map-core/src/capture.ts` — её пишет владелец проекта сам. Можно писать код вокруг неё, но не реализацию.
- **Коммиты — только от учётки владельца, без трейлеров `Co-Authored-By` и без упоминания ИИ-ассистентов**, ни в коммитах, ни в файлах, ни в описании PR. Проект сдаётся от имени владельца.
- В `main` напрямую не пушить: ветка `<кто>/<задача>` → PR (README).
- Интерфейс, тексты и документация — на русском. Технических слов («граф», «тайл», «воркер») пользователь в интерфейсе не видит.
- Импорты в TS — с расширением `.ts` (`allowImportingTsExtensions`): один код работает в Vite, Vitest, tsx и Node.
- Общая логика (геометрия, маршруты, проверки) — только в `map-core` с тестами: её используют и фронт, и бэкенд.
- Пользовательский текст в DOM — через `textContent`/React, не через HTML-строки (метки панорам собираются из DOM-элементов).
- UI не снимать скриншотами без просьбы владельца; проверять тестами, `tsc`, сборкой и запросами к API.
- После каждого этапа обновлять `space-map/docs/STATUS.md`: что проверено и как, что не проверено. Сборка и эмулятор не доказывают работу датчиков и качество склейки — так и писать.
- Новые решения — строкой в `space-map/docs/DECISIONS.md`.

## Известные ограничения

- `heading` демо-панорам условный (0°): снимки Poly Haven не с нашего плана, метки в них стоят по расчёту.
- `react-router@8.5` просит Node ≥ 22.22, локально 22.21 — только предупреждение npm.
