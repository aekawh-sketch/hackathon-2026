# Решения

Полный список — в `TZ.md`. Здесь — решения, принятые при реализации.

| Дата | Решение | Почему |
|---|---|---|
| 2026-10-24 | Тесты конкретных комнат и маршрутов используют неизменную фикстуру бизнес-центра; текущее демо проверяется отдельно | смена демонстрационного плана не должна менять проверяемую геометрию старых тестов или отключать их исходные утверждения |
| 2026-10-24 | Панорамы основного демо включены в статические файлы как `demo-manezh-*`, снимок карты ссылается на эти имена | перенос проекта и запуск без локальной базы не теряют изображения; используется существующий способ загрузки `demo-*` без новых маршрутов API |
| 2026-10-24 | Готовый демо-план хранится экспортом редактора в `demo-plan.json`; `demoVenue()` создаёт отдельную копию | вручную расставленные помещения, места и точки съёмки становятся исходной демонстрацией и не зависят от хранилища одного браузера |
| 2026-10-24 | Вложенная комната может касаться внешней стены родителя | общая стена не означает выход за границы помещения; проверка сохранения должна принимать такой план без сдвига геометрии |
| 2026-10-23 | Монорепозиторий на npm workspaces: `packages/map-core`, `apps/web`, `services/api` | pnpm не установлен; npm хватает |
| 2026-10-23 | Импорты с расширением `.ts`, `allowImportingTsExtensions` | один и тот же код запускают Vite, Vitest, tsx и Node без сборки |
| 2026-10-23 | Кабинет организатора и карта посетителя — одно SPA с ленивыми маршрутами | код кабинета не попадает в бандл посетителя (п. 44) без второй точки входа |
| 2026-10-23 | Метки на плане Konva рисуются в экранных координатах | толщина линий и размер иконок не зависят от зума |
| 2026-10-23 | Клик по пустому месту плана ловит Stage, а не контейнер | Konva шлёт click по `mouseup`, уже после `pointerup` контейнера |
| 2026-10-23 | 3D-модель строится из плана в `map-core` (`buildModel3D`), отрисовка и выгрузка `.glb` — three.js | внешние 3D-файлы не нужны; общие стены соседних помещений склеиваются, иначе мерцают |
| 2026-10-23 | Демо-панорамы — Poly Haven, CC0; `newman_lobby` и `newman_cafeteria` из одного здания | ТЗ 11.3: сцены одной площадки, происхождение помечено в `CREDITS.md` |
| 2026-10-24 | Касания на плане определяются своим hit-test по координатам, Konva только рисует (`listening={false}`) | одинаковое поведение мыши, пера и пальца; нет двойных `tap`/`click` и конфликтов с жестами сдвига |
| 2026-10-24 | Иконки — свой набор линейных SVG-путей (`apps/web/src/ui/icons.tsx`), один для DOM, Konva (`Path`) и 3D (`Path2D`) | эмодзи выглядят по-разному на Android/iOS/Windows; пути весят меньше шрифта иконок |
| 2026-10-24 | Правка плана — чистые функции в `map-core/edit.ts`: после каждой правки граф этажа строится заново (`rebuildGraph`) | ручной граф ломается при сдвиге комнат; авто-граф: узлы по обе стороны дверей, у мест и панорам, рёбра по прямой видимости внутри помещения, веса — метры |
| 2026-10-24 | Комната без двери получает дверь сама (`autoConnect`) — посередине самой длинной общей стены, сначала к коридору или холлу | новая комната сразу попадает в маршруты; организатор может убрать или добавить двери вручную |
| 2026-10-24 | Пока нет бэкенда, демо-площадка из редактора хранится в `localStorage` браузера, `/m/demo` читает её оттуда | можно показать полный цикл «нарисовал → посетитель видит» без сервера; при появлении API заменить на сохранение документа с `revision` |
| 2026-10-24 | Миграции — SQL-файлы `services/api/migrations/*.sql` и свой мигратор (транзакция на файл, advisory lock); запросы — Drizzle | схему читает человек; нет зависимости от drizzle-kit |
| 2026-10-24 | Чужая площадка, неопубликованная или закрытая карта — 404, а не 403 | не раскрываем, что площадка существует |
| 2026-10-24 | Сессия — случайный токен в cookie `httpOnly`, в базе только его SHA-256; CSRF — double-submit (`sm_csrf` + заголовок `x-csrf-token`) | утечка таблицы сессий не даёт войти; SPA и API на одном домене |
| 2026-10-24 | Сохранение опубликованной площадки сразу выпускает новую версию | ТЗ Е7: правки обновляют карту по той же ссылке |
| 2026-10-24 | Хранилище — интерфейс `Storage`, сейчас драйвер «локальный диск» (запись через временный файл + rename) | воркер склейки работает с файлами напрямую через общий том; S3 — вторым драйвером |
| 2026-10-24 | Кадры склейки хранятся с EXIF (поворот применён), публичные панорамы — без метаданных | по фокусному расстоянию из EXIF Hugin считает поле зрения; кадры наружу не отдаются |
| 2026-10-24 | Автосохранение редактора: пауза 0,7 с, одно сохранение в полёте, догоняющее после него; конфликт ревизий останавливает автосохранение до решения человека | не теряем правки и не перезаписываем чужие молча (п. 47) |
| 2026-10-24 | Дверь ставится по центру свободного участка стены (стена минус другие проёмы с отступом 0,15 м от углов и соседей), а не в точку нажатия; двигать и растягивать — только вдоль своей стены | дверь сразу стоит аккуратно; две двери на одной стене не налезают друг на друга |
| 2026-10-24 | Створки — необязательное поле `Opening.door` (`leaves`, `swing`, `hinge`, `openAngle`); нет поля — значения по умолчанию из `doorStyleOf`, дверь открывается в меньшее помещение | старые карты открываются без миграции; план, 3D и рисунок в панели считают створки одной функцией `doorLeaves` |
| 2026-10-24 | После постановки, сдвига и растягивания двери граф маршрутов строится заново | узлы маршрута стоят у середины двери; раньше новая дверь не попадала в маршрут до следующей правки |
| 2026-10-24 | Гостевой вход создаёт отдельный аккаунт и копию демо-площадки, а не пускает всех в один демо-аккаунт | гости не ломают демо друг другу и опубликованную карту `demo`; у гостя нет пароля (хэш-заглушка), только сессия |
| 2026-10-24 | Двери ставит только организатор; `autoConnect` больше не вызывается (функция осталась в `edit.ts`) | решение владельца: автоматические двери вставали не там, где нужно |
| 2026-10-24 | Вырез — контур внутри помещения (`Unit.holes`), а не отдельное препятствие | вокруг выреза — стены (видимость, 3D, граф), внутри — не помещение (`pointInUnit`); узкий вырез заодно даёт перегородку |
| 2026-10-24 | Разделение — прямой линией, которая пересекает контур комнаты ровно дважды | у сложной формы иначе получилось бы больше двух частей; почти горизонтальная/вертикальная линия выравнивается по оси |
| 2026-10-24 | 3D: стены с тёмным «срезом», мягкие тени, подписи и значки — спрайты из canvas; сцена пересобирается только при смене плана, маршрут и выбор меняются без пересборки | камера не прыгает при построении маршрута; в `.glb` уходит только здание и маршрут |
| 2026-10-24 | Точки съёмки рассчитываются по плану: сначала пары точек на оси каждой двери, потом жадное покрытие пола (радиус 7 м, 97 %), потом связь точек внутри помещения | на оси двери отрезок между точками гарантированно проходит через проём — будет переход; покрытие считается по сетке пола, а не «точка в центре», поэтому работает для Г-образных комнат, колонн и коридоров |
| 2026-10-24 | Убранная рассчитанная точка хранится как `origin: 'removed'` и считается «закрытой» | иначе следующий пересчёт поставил бы её снова или соседнюю на 0,5 м рядом |
| 2026-10-24 | `capturePoints` — необязательное поле документа, пересчёт при каждой правке в редакторе, с кэшем по геометрии этажа | старые карты открываются без миграции; правка подписи или места не запускает расчёт |
| 2026-10-24 | «Логичный» маршрут — штраф за поворот в A* (1 м за 90° у посетителя), а не скидка на коридоры | скидка сделала бы вес ребра меньше длины — эвристика A* перестала бы быть допустимой, а длина маршрута — честной |
| 2026-10-24 | Маршрут поверх камеры — своя проекция в `map-core` и SVG поверх `<video>`, без WebXR и новых библиотек | WebXR AR нет в Safari на iOS; при съёмке человек стоит на месте, хватает ориентации телефона; направление привязывается прицелом на дверь, а не компасом |
| 2026-10-24 | Маршрут съёмки на ходу: WebXR, где он есть (ARCore), иначе шаги вдоль линии маршрута | одной ориентации телефона мало — без положения точка едет вместе с человеком; WebXR даёт положение без библиотек, а в Safari его нет — там задача одномерная (идём по линии), шагомеру её хватает |
| 2026-10-24 | Гость сохраняет аккаунт в том же пользователе (`/api/auth/claim`: почта, пароль, `is_guest = false`), а не переносом площадок в новый | ничего не копируем и не теряем: владелец площадок, черновики, версии и сессия остаются прежними |

| 2026-10-24 | Фотосфера в AR собирается на телефоне по повороту камеры из ARCore, а не серверной склейкой; готовность — по покрытию сферы, а не по целям `planCaptureTargets` | воркера склейки нет, а ARCore знает поворот кадра точно — «склеено по датчикам» (ТЗ 5.5) работает сразу; ТЗ п. 67 и так считает готовность по покрытию. `planCaptureTargets` не тронута: цели можно добавить поверх, когда владелец её напишет |
