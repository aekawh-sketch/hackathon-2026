## Роли: пользователь и администратор вместо общего доступа (2026-10-24)

- **Регистрация** — «Пользователь» или «Администратор». Пользователь видит и правит только свои площадки. Администратор видит, правит и удаляет все; регистрация администратором — только с кодом (`ADMIN_INVITE_CODE`, от 8 символов; нет кода — администраторов нет). Уже зарегистрированный становится администратором в «Мои площадки» → «Есть код администратора?» (`POST /api/auth/admin-code`), его площадки остаются при нём. Код проверяется за постоянное время, не больше 10 попыток в час с адреса.
- **`OPEN_ACCESS` убран**: раньше на стенде любой вошедший видел все площадки. Прежние аккаунты после миграции `0003_roles.sql` — пользователи. Гость «без регистрации» снова получает свою копию демо, а не общую площадку.
- Роль приходит в `/api/auth/me`, входе и регистрации (`user.role`); заголовок списка — «Все площадки» у администратора, «Мои площадки» у остальных.
- Проверено: 6 API-тестов на роли (чужая площадка у пользователя — 404; администратор правит и удаляет чужие; без кода и с неверным кодом — 403; код в кабинете; гость — своя копия; сервер без кода); `npm test` — ядро 142, веб 9, API 29; `tsc`, сборка. **В браузере не проверено.**

## Стрелки в панораме вручную, удаление любой площадки (2026-10-24)

- **Стрелки переходов**: редактор → «Открыть панораму» → «Стрелки». Нажать на стрелку, потом в панораме на проход — стрелка встаёт туда и помечается ручной (`setLinkYaw`, `PanoramaLink.manual`); «По плану» возвращает расчёт; «Убрать переход» — в обе стороны (`removeLink`); «Добавить переход» к панораме этажа, которой нет в подсказках (за углом, дальше `linkRange`), с обратной стрелкой у соседа по плану (`addLink`). «◀ 5° … 5° ▶» сдвигает направление всей панорамы: метки и подсказанные стрелки пересчитываются, ручные остаются (`setPanoramaHeading`; «Повернуть по двери» их тоже больше не сбрасывает). ## Загрузка и удаление панорам — исправления (2026-10-24)

Жалоба с телефона: «панорама, загруженная в точку, появляется во всех точках комнаты; удаляется не сразу, а как будто по списку». Разобрано на данных стенда (`e7e97e3`, «Манеж»: 7 загрузок — 1 панорама на плане, панорама в 1,3 м от своей точки).

- **Подбор панорамы для места** (`panoramaForPlace`): только своя (`Place.panorama`) или та, где место отмечено подтверждённой меткой. Убраны «у того же узла», «ближайшая в комнате», «видно через дверь»: свежая панорама без направления (меток в ней ещё нет) показывалась у всех старых мест комнаты, а «Удалить панораму» в карточке места удаляла эту чужую — и подбиралась следующая.
- **Карточка места**: «Удалить панораму» — только у своей; у чужой — пометка «видно в панораме другой точки» и «Перейти к точке съёмки». Кнопки «Переснять» / «Загрузить другую» (своя есть) или «Снять / Загрузить свою».
- **Повторная загрузка в точку заменяет прежнюю панораму** (`addPanoramaAtPoint`), а не кладёт вторую поверх; места, для которых прежняя была своей, получают новую. Снова снимают для места — в той же точке (`capturePointForPlace`).
- **Маршрут съёмки помнит ID точки**, а пересчёт мог отдать его точке в другом месте: если точка дальше 3 м от места съёмки, у панорамы появляется своя точка, чужая не заменяется.
- **«Убрать точку» со снятой панорамой удаляет и панораму** (в подтверждении так и написано). Раньше панорама оставалась на плане без точки — удалить её было неоткуда.
- **Панорамы без точки, которые уже есть в данных**, получают свою точку при открытии редактора; ссылка точки на несуществующую панораму сбрасывается.
- Номер новой панорамы — больше всех занятых: номер удалённой не достаётся новой (старая ссылка или правка второго редактора при слиянии указала бы на чужой снимок).

## Запуск

В Docker: `cp .env.example .env && docker compose up -d --build` → http://localhost:8000. Без Docker:

```bash
cd space-map
npm install
./tools/fetch-demo-panoramas.sh   # один раз; уже лежат в репозитории

# база (один раз): createdb spacemap && createdb spacemap_test
cp services/api/.env.example services/api/.env   # и задать DEMO_PASSWORD
npm run seed -w services/api      # миграции + демо-организатор + опубликованная площадка demo
npm run dev:api                   # http://localhost:8080 , OpenAPI — /api/docs
npm run dev:web                   # http://localhost:5173/m/demo , кабинет — /app ; с телефона — http://<IP-мака>:5173/…
```

Тесты API: `npm test -w services/api` (нужна база `spacemap_test`, она пересоздаётся при каждом запуске).

QR-якорь: `http://localhost:5173/m/demo?a=ENTRANCE` — точка «откуда» уже стоит у входа.

Редактор демо-площадки: `http://localhost:5173/app/editor` (кнопка с карандашом в шапке карты). Правки сохраняются в браузере и сразу видны на `/m/demo`; «Сбросить демо» в меню возвращает исходную площадку.

## Известные ограничения

- `heading` демо-панорам условный (0°): снимки Poly Haven не с нашего плана, метки в них стоят по расчёту, а не по реальным объектам.
