## Своя панорама у места (2026-10-24)

- Новая метка или зона больше не показывает чужую панораму. Раньше карточка подбирала её сама (где место отмечено, ближайшую в той же комнате, откуда видно) — у только что созданного места сразу была панорама, которую для него не снимали.
- Теперь у места своя привязка `Place.panorama`: новое место (`addPlace`, им же создаются зоны) — `null`, карточка пустая, в ней кнопки «Снять фотосферу» / «Загрузить готовую панораму». Снятая или загруженная из карточки панорама привязывается к месту (`setPlacePanorama`) и видна в карточке в редакторе и у посетителя. Удалили панораму — место снова пустое; слияние правок и проверка ссылок знают о привязке; схема API принимает поле.
- Места, сделанные до привязки (поля нет), — как раньше, чтобы у демо не пропали панорамы.
- Проверено: `npm test` — 150 (ядро 123, из них 3 новых на привязку, веб 5, API 22), typecheck, сборка; демо-редактор в безголовом Chrome: новая метка, зона и точка съёмки в зале с панорамами — без превью панорамы. **На стенде с сервером и на телефоне не проверено.**

## Синхронизация телефона и сайта, чистка редактора, удаление площадок (2026-10-24)

- **Правки сливаются сами.** Раньше сохранение, которое упиралось в чужое (телефон снял панораму, пока на сайте правили план), останавливало автосохранение до выбора «чью версию оставить», и правки терялись или зависали. Теперь `mergeDocuments` (map-core) накладывает обе стороны поверх общей базы по сущностям и полям, итог сохраняется сразу; подсказка «Ваши правки объединены с изменениями: …». Окно выбора — только если свести не удалось.
- Одинаковые новые ID (панорамы `pa-N`, точки `cp-N` нумеруются подряд, два телефона дают один номер) — разные сущности: своя получает свободный ID, ссылки на неё тоже. Удалённое любой стороной — удалено, ссылки на него убираются; точка съёмки со снимком не пропадает.
- Редактор спрашивает ревизию раз в 4 с (было 8), карта посетителя — раз в 8 с (было 20).
- **Посетитель не видит точек панорам** — ни на плане, ни в 3D. Панорамы открываются из карточки места и в прогулке по маршруту. В редакторе всё как было.
- **Сводка редактора без лишнего текста:** цифры одной строкой, убраны «Как редактировать», «Как править», пояснения у точки съёмки, места, зоны, выреза, двери — подсказка к инструменту и так над планом.
- **Меню «⋯» в «Все площадки»** — в строке с названием, открывается по кнопке в пределах экрана (раньше уезжало за левый край на телефоне). «Удалить площадку» — окно подтверждения без ввода названия. При общем доступе чужую площадку можно удалить, пока она черновик (гостевые копии); опубликованную и общую демо — только создатель (`canDelete` в списке).
- Проверено: `npm test` — 147 (ядро 120, из них 8 на слияние, веб 5, API 22), typecheck, сборка. Локальный стенд с `OPEN_ACCESS`, безголовый Chrome: телефон (393×780) загрузил панораму в свою точку, сайт сразу переименовал площадку — сохранение сайта слилось без окна, в черновике и панорама, и новое название, посетителю ушла версия 3; телефон подтянул правку. ## Шторка на телефоне (2026-10-24)

- Тянуть можно за всю шапку, в том числе начав с кнопки инструмента: если палец сдвинулся — едет шторка, если нет — нажатие. Вбок — инструменты листаются. Нажатие мимо кнопки больше не прыгает шторкой — переключает только нажатие на ручку.
- Содержимое тоже двигает шторку: вниз от самого верха — сворачивает, вверх, пока она не во весь экран, — разворачивает, дальше тот же жест листает содержимое.
- Быстрый взмах уводит к следующей высоте по направлению, медленный сдвиг — к ближайшей. Шторку можно поймать посреди анимации. Высота во время жеста меняется прямо в DOM раз в кадр, без перерисовки React. Отпущенная над кнопкой после перетаскивания — не нажимает её.
- Общая для редактора и карты посетителя (`ui/Sheet.tsx`).
- Проверено: безголовый Chrome с эмуляцией касаний (393×780, touch-события через CDP): нажатие на инструмент, тяга с кнопки вверх/вниз, быстрый и медленный взмах за ручку, прокрутка инструментов вбок, содержимое вверх/вниз; `npm test` — 139, typecheck, сборка. **На телефоне не проверено.**

## Удаление с подтверждением (2026-10-24)

- «Убрать точку», «Удалить место» и новая «Удалить панораму» спрашивают подтверждение (`ui/ConfirmDialog.tsx`, окно в `body`, Esc — отмена); в тексте — что именно пропадёт и что вернуть можно «Отменить».
- В свойствах места панорама и само место удаляются по отдельности: «Удалить панораму» (под превью) убирает только её — место остаётся; «Удалить место» — только место, панорама остаётся на карте. Если панорама снята не у самого места (в помещении или «видно отсюда»), окно предупреждает, что она пропадёт и из карточек соседних мест. То же «Удалить панораму» есть у снятой точки съёмки — точка снова ждёт съёмки.
- Проверено: `npm test` — 139, typecheck, сборка. **В браузере не проверено.**

## Общая демо-карта и синхронизация (2026-10-24)

- **Правки команды видны посетителям `/m/demo`.** Раньше «Открыть редактор без регистрации» каждому создавало личную копию демо (на стенде их больше десятка, в нескольких по 6–7 панорам) — копии не опубликованы, посетители их не видели. Теперь при общем доступе (`OPEN_ACCESS`) гость входит в общую площадку `demo` (`POST /api/auth/guest` → `shared: true`), а «Редактировать план» на карте ведёт в редактор именно этой карты — после входа гостем туда же. Без общего доступа — по-прежнему своя копия.
- **Редакторы синхронизируются:** раз в 8 с — только номер ревизии (`GET /api/venues/:id/draft/revision`), документ — когда он вырос и у себя нет несохранённых правок; подсказка «Подтянули изменения: …». Есть свои правки — чужие не подтягиваются, при сохранении — прежнее окно «чью версию оставить».
- **Карта посетителя обновляется сама:** раз в 20 с — номер опубликованной версии мимо кэша; новая версия подтягивается без перезагрузки. Фоновая вкладка не спрашивает, при возвращении — сразу.
- **Фотосфера из карточки места:** «Снять фотосферу» (в приложении), «Скачать приложение для съёмки» (браузер на Android), «Загрузить готовую панораму»; точка съёмки у места — неснятая рядом (до 2 м) или новая своя (`capturePointForPlace`; у стены — шаг к середине помещения).
- Проверено: `npm test` — 139 (ядро 112, веб 5, API 22), typecheck, сборка; локальный стенд с `OPEN_ACCESS=true` в безголовом Chrome: два гостя с «Редактировать план» попали в одну площадку; второй переименовал — первый подтянул через ~1 с, посетитель — через 17 с. **Не проверено:** фотосфера из карточки места на телефоне.
- Старые личные копии гостей с панорамами на стенде остались как есть — их панорамы в общую демо сами не переносятся.

## Запуск

```bash
cd space-map
npm install
./tools/fetch-demo-panoramas.sh   # один раз; уже лежат в репозитории

# база (один раз): createdb spacemap && createdb spacemap_test
cp services/api/.env.example services/api/.env   # и задать DEMO_PASSWORD
npm run seed -w services/api      # миграции + демо-организатор + опубликованная площадка demo
npm run dev:api                   # http://localhost:8080 , OpenAPI — /api/docs
npm run dev:web                   # http://localhost:5173/m/demo , кабинет — /app ; с телефона — http://<IP-мака>:5173/…
```

Тесты API: `npm test -w services/api` (нужна база `spacemap_test`, она пересоздаётся при каждом запуске).

QR-якорь: `http://localhost:5173/m/demo?a=ENTRANCE` — точка «откуда» уже стоит у входа.

Редактор демо-площадки: `http://localhost:5173/app/editor` (кнопка с карандашом в шапке карты). Правки сохраняются в браузере и сразу видны на `/m/demo`; «Сбросить демо» в меню возвращает исходную площадку.

## Известные ограничения

- `heading` демо-панорам условный (0°): снимки Poly Haven не с нашего плана, метки в них стоят по расчёту, а не по реальным объектам.
- `react-router@8.5` просит Node ≥ 22.22, локально 22.21 — только предупреждение npm, в браузере не влияет.
